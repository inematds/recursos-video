What it is

A catalog, not a single product

This page brings together tools that evolved in parallel. The idea is to stop rediscovering “which project does X”: find the right path here in seconds and go straight to the guide.

🧭 7 paths

Deterministic, cloud AI, local AI, image, direction, orchestration, and post-production. Every video request falls into one of these.

🏠 Local-first

Most run on your machine/DGX: flux2-klein (image), inemavox (voice), HyperFrames/Remotion/pixflow (rendering). Local video AI is optional.

🔗 Everything connected

The orchestrators reuse the same building blocks — direction from MDD, images from inemaimg, voice from inemavox, rendering from HyperFrames.

Look before you invent

What has actually worked

Before writing a new pipeline, see what has already been measured. These five solved the problem and left notes — including about the flaws.

videos-agnes — story → narrated film, US$ 0

Gold standard for an animated story: derived character anchors (not generated in parallel), character description repeated in every scene, narration by paragraph, no on-screen text. Outputs in ~/projetos/output/videos-agnes/.

agnesfree / agnes-nei — the Agnes API tested across ~70 calls

NOTAS-API.md includes the rules that affect your bottom line, the model's flaws, and the rate limits. Includes the filter trap: a child character deterministically returns HTTP 400.

klingaimcp + klingai-nei — Kling with its own signature

Access via MCP and CLI, with account, defaults, and dubbing with a cloned voice. API notes measured in ~/projetos/wifi/KLING-NOTAS-API-2026-08-02.md.

pixflow — film from a still image, without video AI

2.5D parallax with real depth, grain, LUT, and vignette. Deterministic: same input, same result — the opposite of a video generator.

inemaref — content factory based on a reference

The same character carries through a folder, comic, motion comic, and entire series, maintaining visual consistency.

How to choose a path

From request to the right resource

Start with the type of video you want. The flow below points you in the right direction; the catalog has details on each component.

Topic / link / images→ Choose a path→ Direction / plan→ Image + voice→ Render→ MP4

🎞️ I want something reproducible, without video AI

Camera/parallax over images, motion graphics, animated comics. → pixflow, inemafilme, inemaref, HyperFrames, Remotion.

📖 I have a story and want the film

Story, episode, consistent character. → videos-agnes (simple, US$ 0) or videoanima (with shot breakdown and swappable provider).

🤖 I want AI-generated motion

Cloud/subscription: klingaimcp, seedance2. Local on GPU: VideosDGX2 (Wan 2.2), HuMo, skyreelsv3.

🗣️ I want someone speaking on screen

Scripted talking avatar. → heygenmcp (subscription credits), videosavatar, or HuMo for local lip-sync.

🎬 I want to go from a topic/link to a video, automatically

Explainer, app demo, video lesson, marketing reels. → video producer, video-explicativo, video-demonstrativo, videos-cursos-inema, timesmkt3.

✂️ I already have a video and want to edit it

Dub, cut fillers, add captions, replace the soundtrack. → dublar pro, inemavox, musicaclone, inemadlp.

Prerequisites

What needs to be running

The local-first paths depend on a few services and binaries. Start the ones your path uses.

🖼️ inemaimg (image)

flux2-klein server and more.

# starts the image server
cd ~/projetos/inemaimg
docker compose up # :8000

🎙️ inemavox (voice)

Narration / cloning / SFX.

# voice daemon
cd ~/projetos/inemavox
uvicorn app:api # :8010

🧰 Rendering foundation

Node + FFmpeg + Chrome (HyperFrames).

# quick check
node -v && ffmpeg -version
echo $CHROMIUM_BIN
Quick guide · from topic to video

A typical workflow (explainer/producer)

Example of the most common journey: a topic becomes a professional video by reusing the building blocks. Switch the skill based on the type (explainer, demo, series, marketing).

1

Upload an image and voice

The orchestrators call these services; keep them running.

cd ~/projetos/inemaimg && docker compose up -d   # image :8000
cd ~/projetos/inemavox && uvicorn app:api &        # voice :8010
2

Choose a path in the catalog

Explainer → video-explicativo. App demo → video-demonstrativo. Pro/landing page → videoprodutor. Story → videos-agnes or videoanima. Series/comic → inemaref.

# each skill responds to help
/video-explicativo "o que é engenharia de contexto"
3

Validate before spending

For paths using a paid provider, check the pacing and cost before the first call.

python3 rodar.py exemplo --so-decupagem   # videoanima: validates without generating
4

Let the queue render

For batches, queue them in mkivideos and move on — it serializes GPU work and notifies you when it’s done.

/mkivideos explicativo "tema"   # queues and renders in the background
5

Get the MP4

The output goes into the default output folder; move the final file to its destination.

ls ~/projetos/output/<projeto>/   # MP4 16:9 and/or 9:16
